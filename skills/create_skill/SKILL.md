# 创建新 Skill 的规范

## 目录与格式

每个 skill 是 `skills/<技能名>/SKILL.md` 一个文件,结构:

```
---
name: <技能名,小写加连字符,如 code-review>
description: <何时使用:写成触发条件,让模型能凭这句话判断任务是否匹配>
---
<正文:分步骤的工作指南>
```

## 创建流程

1. 先与用户确认:技能名、适用场景、大致步骤;信息不够就先问;
2. 用 write 工具创建 `skills/<技能名>/SKILL.md`,严格按上面的格式;
3. description 是自动匹配的依据,必须写"什么情况下使用",不要写"是什么";
4. 正文写步骤化指南:精确保留命令、路径、代码片段;一个 skill 只解决一类任务;
5. 创建完成后告知用户:
   - 本会话可立即用 load_skill("<技能名>") 加载使用(不依赖清单);
   - 下次会话它会自动出现在 <skills> 清单里。

## 质量红线

- description 空泛(如"辅助编程")是废技能,必须可判断;
- 正文超过 100 行说明拆成了多个技能的活,精简或拆分;
- 不要在 skill 里写与该技能无关的内容;不要复制本文件的格式说明到新技能。
