# 创建 Skill

Skill = 按需注入的工作指南:system prompt 里只放清单(名+描述),任务匹配时模型调用
load_skill 加载全文。本技能教模型(也就是你)按规范创建高质量的新技能。

## 核心原则

1. **上下文窗口是公共财产**:默认模型已经很聪明,只写它没有的知识;每段都问"值得它的 token 吗"。优先用简短示例,不要长篇解释。
2. **description 是唯一触发机制**:"何时使用"的信息全部写在 description 里,绝不写进正文——正文只有触发后才被加载,写在正文里的使用时机没人看得到。description 要包含:技能做什么 + 具体触发短语(用户可能怎么说)。
3. **自由度匹配任务**:多种做法都可行 → 文字指南(高自由);有首选套路但允许变化 → 伪代码(中);操作易错、必须严格一致 → 具体脚本(低)。
4. **SKILL.md ≤ 100 行**:更深的材料拆到 `references/` 子目录(从 SKILL.md 链接并在正文说明何时读),或做成 `scripts/` 脚本(反复重写的代码固化下来,执行时不必读进上下文)。

## 解剖结构

```
skills/<技能名>/
├── SKILL.md        必需:frontmatter(name + description)+ 正文指南
├── scripts/        可选:可执行脚本(确定性、省 token)
├── references/     可选:按需加载的深度文档
└── assets/         可选:产出用的模板资源(不进上下文)
```

不要创建 README、CHANGELOG 等辅助文档——技能只为 AI 干活服务。

## 创建流程(按顺序)

1. **理解**:先向用户要具体用例("这个技能会被怎么用?用户会说什么话来触发它?"),信息不够就先问;
2. **规划**:分析用例,列出需要的 scripts/references/assets(反复重写的代码 → 脚本;大段领域知识 → references);
3. **创建**:用 write 工具创建 `skills/<技能名>/SKILL.md`(目录名 = 技能名,小写连字符);只创建真正需要的子目录;
4. **编辑**:正文用祈使句写步骤化指南,精确保留命令、路径、代码片段;写了脚本就实际运行测试一遍;
5. **验证**:重读并对照——name 与目录名一致?description 以使用时机开头?步骤能用现有工具执行?SKILL.md 精简?
6. **交付告知**:本会话可立即用 load_skill("<技能名>") 加载;下次会话自动出现在 <skills> 清单。

## 红线

- description 空泛(如"辅助编程")是废技能——必须能凭它判断任务是否匹配;
- 一个技能只解决一类任务;超过 100 行就拆分;
- 不复制本文件的格式说明到新技能正文。
